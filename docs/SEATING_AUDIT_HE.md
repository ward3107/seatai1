# סקירת מנוע ההושבה ורצף העבודה

## היקף

נבדקו בקוד המנוע הגנטי, פונקציית הניקוד, ספירת הפרות אילוצי חובה, הנעילות, ההחלפות הידניות, חיבור ה־Worker, תוכנית הסבבים והיסטוריית השכנים. זו סקירה הנדסית ובדיקות עם נתונים בדויים; לא אימות חינוכי, הוכחת אופטימליות או פיילוט בשטח.

## מה המערכת מפעילה

המנוע הפעיל הוא ClassroomOptimizer: חיפוש גנטי, התחלות מרובות ושיפור מקומי באמצעות החלפות. optimize ו־optimizeAsync מפעילים אותו מנוע. ערכי שמות אלגוריתמים נוספים בממשק הטיפוסים אינם מעידים על מימוש פעיל שלהם.

אילוצים שסומנו כחובה מקבלים קנס מספרי גבוה. מדובר בחיפוש היוריסטי: הפרה בתוצאה אינה הוכחה שאין פתרון אפשרי. אין להציג תוצאה כפתרון מיטבי מוכח.

## תוקן בסבב זה

| ממצא | התיקון |
|---|---|
| ציון וספירת הפרות נשארו ישנים אחרי החלפה ידנית | הערכה מחדש של הסידור ללא הרצת חיפוש; undo/redo משחזרים גם את המדדים |
| הגנה על נעילות הייתה רק בממשק ההחלפה | נוספה הגנה גם בפעולת ה־store |
| יעד החלפה לא קיים יצר רשומת undo | אימות המושבים קודם לשמירת ההיסטוריה |
| שינוי ידני לא נספר לתזכורת גיבוי | מונה השינויים מתעדכן |
| תלמיד ללא שכנים מאוכלסים לא קיבל ניקוד לצורך מקדימה/אזור שקט | ניקוד הצרכים מתבצע לפני דילוג על השוואת שכנים |
| תוכנית סבבים לא העבירה מקומות נעולים למנוע | חילוץ משותף של הנעילות והעברתן בכל תקופה |
| הערת קוד הציגה כשל בחיפוש כהוכחת אי־אפשרות | הובהר שהספירה מתארת את הפתרון שנמצא בלבד |
| שינוי נתוני ניקוד, משקלים או אילוצים השאיר מדדים ישנים | נוספה הערכה מחדש אחידה של הסידור הקיים, כולל אילוצי חובה |
| שינוי בהרכב הכיתה השאיר סידור חלקי | הוספה, מחיקה או החלפה של הרשימה מבטלות את הסידור והיסטוריית ה־undo התלויים בהרכב |
| מחיקת תלמיד השאירה הפניות יתומות | ניקוי חברויות, התנגשויות, כל סוגי האילוצים, שאלון והיסטוריית מיקומים |
| היסטוריית שכנים פירשה עבר לפי צורת החדר הנוכחית | כל רשומה חדשה שומרת את הגדרת החדר; רשומות ישנות נשארות תואמות לאחור |
| "איזון לימודי" תגמל דמיון למרות שממשק המשתמש הבטיח ערבוב | נוספו מטרות מפורשות: רמות מעורבות, מוכנות דומה ותמיכת עמיתים; הציון מותאם למטרה שנבחרה |
| ניקוד התנהגותי דומה קירב גם תלמידים הזקוקים לתמיכה רבה | הניקוד מבזר צמדי תמיכה גבוהה ומעדיף סביבה התנהגותית מאוזנת |
| חישוב תוכנית הסבבים בוצע ב־main thread | נוסף Worker ייעודי עם fallback משותף, כך שחיפוש כבד אינו חוסם את הממשק בדפדפנים תומכים |
| תוצאה שמורה לא תיעדה במדויק כיצד נוצרה | נוספו גרסת מנוע, זמן יצירה, הגדרות, נעילות, הקשר סבבים, חתימת קלט והבחנה בין תוצאה מותאמת לתוצאה שחושבה מחדש |
| לא היה שער קבוע לביצועים ולאיכות מול נקודת ייחוס | נוסף benchmark דטרמיניסטי לכיתות של 12, 30 ו־48 תלמידים, כולל תקינות, אילוצי חובה, גבולות ציון, זמן ורף איכות מול סידור סדרתי |

## אימות נוסף

בדיקות עם שלושה זרעים קבועים בחמש צורות חדר: שורות, קבוצות, ח׳, מעגל ושורות מותאמות. נבדקים שימור כל התלמידים, היעדר כפילויות, מיקומים ייחודיים, שימור תלמיד נעול וציון סופי סופי־מספרית. נוספו בדיקות לשינוי ידני שמפר אילוץ חובה, undo/redo, תלמיד מבודד ונעילות בסבבים.

ה־benchmark אינו מדידת יתרון חינוכי או השוואת מהירות במכשירי בית ספר. הוא שער רגרסיה הנדסי מול נקודת ייחוס קבועה, לא הוכחת אופטימליות ולא השוואה בין מנועים עצמאיים.

## פערים שנותרו להמשך

1. נדרשת מדידת זמן ויציבות במכשירי היעד וברשתות של בתי הספר; benchmark של CI אינו מחליף בדיקת שטח.
2. נדרשים מקרי אמת מאושרים ומדדי זמן, שיעור הפרות וכמות תיקונים ידניים לפני טענה להתאמה חינוכית או יתרון מסחרי.
3. נדרשת בדיקה אנושית של אסטרטגיות ההושבה עם מורים ואנשי מקצוע; בחירת אסטרטגיה צריכה להישאר בידי המורה ולא להפוך להחלטה אוטומטית סמויה.

## סדר עדיפויות

קודם עקביות בין תלמידים, אילוצים ותוצאות קיימות; לאחר מכן היסטוריית סבבים והסבר לציון; ורק אז שינוי האלגוריתם או הוספת מנוע נוסף. אין צורך להחליף את המנוע רק בגלל שמו — יש להשוות תוצאות על מקרי מבחן עם פתרונות ידועים.
